# GUNT Desktop v2.4 최종 구현 보고서

2026-10-16. [모니터 깜빡임 수정·Windhawk 2개 추가 적용 보고서](v24-flicker-mods-report.md)를 함께 참조한다. 최신 활성 모드는 11개다. 기존 프로젝트를 이어 수정했다. 실행·화면·로그 증거와 미검증 사항을 구분한다. 최종 수락 조건 전체가 무조건 완료된 것으로 표시하지 않는다.

## 1. 기존 환경 분석

Windows 11 Home 25H2, 빌드 26200.9711. Samsung 960XHA, Intel Core Ultra 5 226V(8코어/8스레드), Arc 130V, 사용 가능 메모리 약 15.54GiB. Rainmeter 4.5.28.3936, Windhawk 1.7.3, Flow Launcher 2.1.4, Lively 2.2.1.0을 유지했다.

세 화면은 주 2880×1800/175%, 위쪽 1920×1080/100%(442,-1080), 오른쪽 2160×1440/150%(2880,163)이다. 진행 중 사용자가 옮긴 시스템 모니터의 수동 위치를 유지한다. 14:40 검증 당시 위젯은 위쪽 100% 화면 오른쪽이었다. 이후 사용자가 주 화면으로 옮긴 위치(175%)를 유지했다.

## 2. Floating Dock

기존 중앙 기준 배치를 유지하고 오른쪽 제어 Dock 앞까지 필요한 만큼만 왼쪽으로 옮기는 계산을 유지했다. 화면 왼쪽 정렬로 바꾸지 않았다. 높이 60 DIP, 아이콘 38 DIP, Windows 고정 앱·실행 앱·상황 메뉴·창 전환을 보존했다. 실제 16개 앱 버튼, 겹침 없음, Chrome 창 전환을 확인했다. 최대 앱 수의 오버플로 스트레스는 미시험이다.

## 3. 오른쪽 컨트롤 Dock

네이티브 트레이를 유지하고 spacing 모드 1.4를 적용했다. 초 단위 시계와 한국어 날짜가 갱신되는 것을 확인했다. Taskbar Volume Control 휠로 실제 기본 오디오 출력이 100%→98%로 바뀌는 것을 확인한 뒤 100%로 복구했다. 실제 장치 변경·최대 숨김 아이콘 수는 추가 시험 대상이다.

## 4. 상단 바

기존 WinForms AppBar를 유지했다. 42 DIP 높이와 한국어 왼쪽 메뉴를 유지하고, 오른쪽 5개 텍스트를 Fluent 20 Regular 계열의 성능·이미지·달·화면·설정 아이콘으로 바꿨다. 아이콘 20 DIP, 클릭 영역 36 DIP, 간격 8 DIP다. hover/pressed/focus 표시와 S-Core 한국어 툴팁을 제공한다.

브랜드는 정확한 `𝓖𝓤𝓷𝓣_𝟎𝔁𝟗`다. Cambria Math를 GDI+로 렌더링해 GDI TextRenderer의 빈 글자 문제를 해결했다. Windows 시스템 아이콘 글꼴은 바꾸지 않았다.

5개 버튼의 MSAA PushButton 이름과 실제 모니터 토글을 확인했다. Alt+Shift+G로 첫 버튼에 포커스, Tab으로 이동, Space로 실행한다. 실제 키보드 입력도 통과했다. UIA ControlType은 WinForms 사용자 그리기 특성으로 Pane으로 노출되며 MSAA 이름·기본 동작을 제공한다.

## 5. 시스템 모니터

S-Core Dream 4/5/6와 Manrope를 범위별로 적용했다. 숫자는 S-Core의 고정 숫자 폭을 사용하며 모델명은 Manrope를 사용한다. 원래의 과도한 빈 공간·큰 둥근 카드를 줄이고 한 패널, 얇은 구분선, 6 DIP 반경, 16 DIP 패딩으로 정리했다.

CPU 숫자와 최신 점은 같은 표본이다. 그래프는 0–100% 고정 축, 30/60/120초 시간창, 1000/2000/5000ms 갱신을 지원한다. 7개 고정값을 별도 테스트 스킨에서 실제 픽셀로 대조했고 최대 약 0.51%p 오차, 50%는 정확히 중간에 표시됐다. 테스트 고정값을 실제 측정값으로 사용하지 않았다.

네트워크는 실제 라우팅 인터페이스의 바이트 차이/경과 시간이다. 다운로드 보라·업로드 청록, 축 최대 KiB/MiB/s 표시, 연결 속도와 세션 누적량을 표시한다. 동적 축 변경 때 원시 이력 전체를 다시 투영한다. CPU·네트워크 그래프는 독립적으로 저장하며 기본 높이에서 둘 다 접으면 202 DIP를 회수한다. 화면 작업영역이 부족하면 그래프 높이를 48/40 DIP까지 줄여 모든 측정 항목을 화면 안에 배치하며 글자 크기와 실제 DPI는 유지한다.

C:/D:를 ‘저장공간’ 아래 별도 용량·여유·사용률 행으로 표시한다. 둘은 같은 Samsung NVMe의 파티션이다. E: USB는 고정 저장공간 목록에서 제외했다. 물리 디스크 매핑을 기록하고 공유 SSD 온도는 한 번 표시한다.

CPU DTS 코어 온도, Arc GPU 코어 온도, Samsung SSD 온도를 실제 HWiNFO 가젯 값과 연결했다. 20회 표본의 CPU 53–65°C, GPU 50–52°C, SSD 49–50°C를 확인했다. 이는 당시 표본이며 고정값이나 정상 범위 보장이 아니다. CPU를 패키지 온도라고 잘못 부르지 않는다. 보고되지 않은 package power·팬·전력은 표시하지 않는다.

간단히/자세히는 아이콘·글자·여백 전체가 클릭된다. 헤더를 잡아 이동하면 모니터 ID와 작업영역 상대 DIP 좌표를 저장한다. 새로고침과 시작 복원 때 유지한다. RAM 총량 초기 미준비 상태의 잘못된 백분율을 막고 ‘수집 대기’를 표시한다.

## 6. Windhawk 확장

후속 작업에서 Settings Styler 1.1과 Better file sizes 1.6을 실제 적용·검증해 현재 총 활성은 11개다. 세부 검증은 상단 추가 보고서에 있다.

기존 Taskbar Styler 1.10, Taskbar height and icon size 1.3.10, Clock Customization 1.8.1, Notification Center Styler 1.7을 유지했다.

초기 추가 활성은 Thumbnail Reorder 1.1.5, Tray spacing 1.4, Volume Control 1.3.1, Alt+Tab per monitor 1.2, Start Menu Styler 1.7이다. 공식 소스 커밋과 SHA256을 기록하고 하나씩 컴파일·활성화했다.

File Explorer Styler 1.7도 시험했지만 Taskbar Styler의 XAML 초기화 재시작 안내 0x8000FFFF가 발생해 비활성화했다. 재시작 안내에는 No를 선택했으며 Explorer를 재시작하지 않았다. 이후 작업 표시줄 재적용·Dock 검사와 기본 탐색기 재열림을 통과했고 안내가 다시 나타나지 않는 것을 확인했다. 이 조합은 안정성 우선으로 제외한다. 자세한 호환성 표는 v24-windhawk-matrix.md를 참조한다.

## 7. GUNT 제어 센터

.NET Framework 4.8 WPF 실행 파일을 실제 빌드했다. 새 SDK·Electron·서버 없이 기존 csc로 빌드한다. MVVM의 설정 모델과 공유 구성 서비스를 사용한다. 창을 닫으면 제어 센터의 백그라운드 프로세스는 남지 않는다.

개요, 글꼴·상단 바, 시스템 모니터, 하드웨어 센서, 배경·프로필, 화면·시작 복원, Windhawk, 진단·복구 화면을 제공한다. 폰트·브랜드·아이콘·표시 항목·독립 그래프·시간창·갱신 간격·C/D 선택·위치 잠금·시작 설정을 바꿀 수 있다. 실제 센서 식별값을 선택해 연결한다.

적용 전 입력 검사와 버전 백업, 원자적 저장, 실제 내보내기/창 확인, 실패 복구를 수행한다. 실제 WPF 체크박스 적용과 원상 복원, 별도 경로의 강제 적용 실패 복구를 시험했다. Windhawk는 실제 INI 상태를 읽고 공식 관리 창을 연다. 지원하지 않는 임의 관리 API나 가짜 슬라이더를 만들지 않았다.

## 8. 작업공간 프로필

기존 개발·일상·게임·집중 프로필과 이전 상태 복원을 유지했다. 오래된 캡처 프로필을 적용할 때 새 설정을 통째로 지우지 않도록 병합하며 수동 모니터 위치를 보존한다. 집중 아이콘의 강조는 실제 위젯 숨김·수동 배경 정지 상태를 함께 확인한다. 알림 억제나 드라이버 변경은 수행하지 않는다.

## 9. 배경 및 절전

사용자가 현재 선택한 Lively 배경을 보존한다. 이전 Gojo 경로로 강제 되돌리지 않는다. Lively의 현재 WallpaperLayout을 복원 설정으로 채택하며 정적 모드로 바꾸기 전 마지막 배정을 저장한다. 기존 정적 65% 배경은 fallback으로 남긴다.

기존 Lively의 전체 화면·배터리·절전 모드 Pause 정책과 음량 0을 보존했다. 앱 포커스는 무시, 가림 감지는 Lively Grid 방식이다. 재생·정지·정적 전환·Lively 설정은 실제 공식 명령을 사용한다. 실제 배터리 지속시간·잠금·게임별 전력 절감은 측정하지 않았다. 현재 사용자가 고른 라이브 프로젝트에 임의 밝기 변경을 주입하지 않았다.

## 10. 멀티 모니터 및 시작 복원

세 화면에 실제 헤더 드래그를 수행해 175/150/100% 배율, 음수 y 좌표, 화면 경계, 새로고침 복원을 통과했다. 비동기 재배치가 끝난 후 검사한다. 전역 디스플레이 구성은 바꾸지 않았다.

기존 현재 사용자 Run 항목과 start-hidden.vbs를 유지했다. 배경·레이아웃·Rainmeter·Flow·Windhawk·상단 바를 중복 없이 복원한다. 직접 실행 검사는 통과했지만 실제 로그아웃/재부팅은 하지 않았다. HWiNFO 관리자 로그인 작업은 별도 승인·등록 상태를 state/hwinfo-startup.json으로 확인한다.

## 11. 성능

작업 중 비교 표본이며 실험실 유휴 상태가 아니다. 8논리 프로세서 기준으로 정규화했다. Explorer·Lively·사용자 앱의 부하를 GUNT에 합산하지 않는다.

| 상태 | 시간 | 상단 바 CPU | Rainmeter CPU | 두 프로세스 작업 집합 합계 |
|---|---:|---:|---:|---:|
| 상세 + 제어 센터 열림 | 61초 | 0.148% | 0.068% | 113.1MiB |
| 간단히 + 제어 센터 닫힘 | 30초 | 0.122% | 0.026% | 105.3MiB |
| 그래프 숨김 + 앱 닫힘 | 30초 | 0.135% | 0.039% | 106.3MiB |
| 위젯 숨김 + 앱 닫힘 | 30초 | 0.090% | 0.032% | 106.3MiB |

해당 제어 센터 열림 표본은 CPU 약 0%, 작업 집합 약 213MiB였다. 닫은 뒤 프로세스가 없는 것을 확인했다. 짧은 표본 차이로 전력 절감량을 단정하지 않는다. 위 표는 온도 연결 전 표본이다. 온도 연결 후 61초 표본은 상단 바 0.180%/65.1MiB, Rainmeter 0.103%/37.0MiB, HWiNFO 0.550%/29.3MiB였다. HWiNFO private memory는 365.4MiB로 작업 집합과 구분한다. 제어 센터는 닫혀 있었다. 이때 상단 바+Rainmeter+HWiNFO의 CPU 합은 약 0.83%였다. 시나리오 시각·벽지 가림·사용자 작업이 달라 단순 전후 개선율을 계산하지 않는다. 원본은 logs/v24-performance-sensors-final.json이다.

## 12. 디자인 검증

kill-ai-slop 스킬의 원칙을 데스크톱 구현에 맞춰 검토했다. 얇은 선, 작은 반경, 실제 데이터와 고정 숫자 정렬, 하나의 아이콘 계열을 사용했다. 브랜드·한국어·아이콘의 실제 스크린샷을 확인했다. 제어 센터 선택 상자와 제목 표시줄도 어두운 색으로 맞췄다. 다중 DPI에서 위젯 위치와 글자 겹침을 검사했다.

## 15. 원상복구

pre-v24 전체 기준 백업과 단계별 체크포인트를 보존했다. v24-recovery.md의 구성 요소별 rollback-v24.ps1을 사용한다. 복원 대상 해시를 확인하며 복구 직전 파일도 다시 백업한다. 전체 복구를 자동으로 실행하지 않았다. 글꼴 복구는 GUNT의 현재 사용자 등록만 되돌리며 시스템 아이콘 글꼴은 건드리지 않는다.

## 16. 남은 제한사항

실제 로그인 복원과 배터리/잠금/게임 시나리오는 미시험이다. HWiNFO 센서 상태 창을 닫으면 보고가 중단될 수 있으므로 최소화해야 한다. CPU 패키지 온도·전력으로 추정하지 않는다. 파일 탐색기 Styler는 충돌 때문에 꺼져 있다. 별도 센서 드라이버나 LHM을 함께 설치하지 않았다. Start 검색과 일부 모드의 세부 입력은 수동 검증이 남는다. 제어 센터는 v2.4에 필요한 설정 범위이며 v2.3의 모든 잠재적 기능을 새로 구현했다고 주장하지 않는다.

## 17. 최종 결과

기존 Dock과 라이브 배경을 보존하면서 한국어 폰트·브랜드·상단 아이콘, 실제 온도를 포함한 모니터, 정확한 시간축 그래프·독립 표시, 저장공간, 모니터별 위치 복원, WPF 관리 앱을 적용했다. 충돌한 모드는 해제하고, 미검증 항목과 복구 방법을 기록했다.
