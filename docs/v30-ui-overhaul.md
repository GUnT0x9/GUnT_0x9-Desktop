# 3.0 UI 구현 기록

현재 프리뷰: **3.0.0-dev.3**. [이번 결과](v30-dev3-report.md) · [전후 화면](visual-history.md#v300-dev3--ui-polish--optimization). 아래 dev.2 기록은 당시 결과로 보존한다.

## dev.2 — 시각 완성 및 Windows 검증

상태: 주요 UI 구현과 Windows 네이티브 검증을 수행한 **개발 프리뷰**. 정식 3.0 출시 또는 모든 환경의 검증 완료를 의미하지 않는다.

## 실행 환경과 기준

- 기준 커밋: `feat/v30-ui-foundation` / dev.1 `9e5e928`. v2.6 `3ae33e2`, main의 v2.5 이력 유지.
- 에이전트는 WSL2 Ubuntu 22.04.5에서 실행된다. `systemd-detect-virt` 결과는 `wsl`이다.
- Windows PE 자동 실행을 위한 WSLInterop binfmt 등록이 없어 직접 `powershell.exe` 실행은 실패한다. `/init` 인터프리터 명시 호출로 Windows 빌드 26200의 PowerShell과 GUI 실행을 확인했다. 실행 파일 손상으로 판정하지 않는다.
- 시스템의 binfmt 설정을 바꾸지 않았다. 기존 Windows Framework64 `csc.exe`와 빌드 스크립트로 실제 앱을 빌드했다.
- 실제 연결 화면은 1개, 2880×1800, DPI 168(175%). 초기 비 DPI-aware PowerShell의 가상 해상도와 구분했다.

## 개발 프로젝트 목록

카드 대신 재활용 목록에 이름, 기존 탐지 서비스의 프로젝트 유형, 실제 Git 분기와 수정/미추적 개수, 최근 사용 시각, 행 내부 즐겨찾기를 표시한다. 확인 실패를 정상 상태로 대체하지 않는다.

메타데이터는 실현된 행에서만 요청하고 동시 조회는 2개로 제한한다. 검색은 메모리에서 필터링하며 조회 결과가 늦게 도착해 다른 선택을 덮어쓰지 않게 한다. 선택 저장은 작업 스레드에서 수행하고, 곧바로 다른 페이지나 실행 동작으로 이동해도 새 프로젝트 문맥이 먼저 반영되도록 연결했다.

넓은 화면은 루트/목록/상세 3열, 중간 화면은 목록/상세 2열과 접이식 루트 설정, 최소 화면은 상세를 목록 아래에 배치한다. 데이터가 적을 때 목록 높이를 줄이고 주요 실행 동작을 모았다. 나머지 기존 실행 도구는 접기 영역에 모두 보존한다.

## 개발 세션 편집기

프리셋과 본문 편집기를 연결했다. 각 단계에 이름·대상, 사용 여부, 동작 선택, 위/아래 이동, 제거를 제공한다. 선택 속성은 해당 단계 안에서 펼친다. 접힌 속성·세션 실행 설정·전체 이력은 펼칠 때 생성한다.

매개변수는 기존 실행 모델이 지원하는 등록 도구 ID, 세션 터미널·프로필, 프로젝트 실행 설정을 편집한다. 실행 엔진이 소비하지 않는 임의 CLI 인수 필드는 추가하지 않았다. 실행 정의와 읽기 전용 미리보기를 분리하고 기존 시작 전 요약·명령 동의·단계별 결과를 유지한다.

프리셋 전환·페이지 이동·닫기에서 미저장 편집을 보호하고 Ctrl+S로 저장한다. WPF 선택 이벤트에서 이전 SelectedValue가 보이던 경로를 실제 AddedItems 기준으로 수정했다. 프로젝트별 설정을 상속한 터미널의 미리보기도 올바르게 표시한다.

## 배경화면 그리드

WPF 기본 재활용 ListBox가 행 묶음을 가상화하고 실현된 행 안에만 타일을 만든다. 폭에 따라 1–6열로 바뀌며 각 썸네일은 16:9 영역에서 원본 비율을 유지해 채운다.

검색·즐겨찾기 필터, 현재 적용 배경과 화면 배치, 텍스트와 테두리를 함께 쓰는 선택 상태, 전체 이름 툴팁, 실제 썸네일 없음 안내를 제공한다. 적용 동작은 그리드 위에 배치했다. 방향키로 선택하고 Enter로 썸네일을 미리본다. 실제 배경 적용은 기존 확인 절차를 거친다.

240px 축소 디코딩, Freeze/OnLoad, 최대 64개 이미지 캐시를 유지한다. 비동기 완료는 Dispatcher에서 UI에 반영한다. Lively 렌더러나 사용자의 현재 배경을 교체하지 않았다.

## 공통 시각 보정

- 어두운 배경에서 검게 보이던 Expander 제목 수정.
- 검색 안내, 보라색 포커스, 중복 패딩 없는 입력 템플릿.
- 선택 입력의 접근성 이름과 단계 편집 이름 제공.
- 빠른 패널·팔레트를 네이티브 도구 창으로 정리하고 닫기 재진입·Escape 후 소유 창 포커스 복귀 보완.
- 빈 자동화 목록의 큰 표면을 다음 행동 안내로 교체.
- 모니터 설정의 단위·설명을 사용자 표현으로 정리. 측정·그래프·센서 의미는 변경하지 않음.
- MainWindow의 단축키 설정을 매 키 입력마다 파일에서 읽지 않도록 변경. 활성화와 설정 작업 후 갱신.

## 보존 및 한계

기존 프로젝트·세션 저장 형식, 실행 서비스, v2.6 기능, 공식 브랜드, Rainmeter 측정, Lively 연동과 Dock 보류 정책을 유지했다. Explorer 재시작·원인 조사·설정 초기화·배경 적용·새 전역 키 등록을 수행하지 않았다.

최소 창에는 세로 스크롤이 필요하다. 실제 사용 데이터의 프로젝트는 1개, 배경은 16개이며 큰 목록은 격리된 500개 데이터로 추가 검사했다. 자동화는 실제 빈 목록 상태를 검토했다. 스크린리더·고대비·장시간 메모리 추세·다른 DPI·물리 화면 재연결은 후속 검증 대상이다.

### 실제 화면에 남은 보정 항목

- 개요·진단의 센서 상태에는 `설정 필요`와 원시 품질 이름이 중복된다. 상태 판정 서비스의 의미를 유지하면서 표현을 정리할 여지가 있다.
- 최소 780×560 DIP에서는 상세 실행 동작과 세션 하단이 첫 화면 밖에 있다. 바깥 세로 스크롤로 접근하며, 갤러리는 내부 목록 스크롤도 사용한다.
- 긴 배경 이름은 타일에서 말줄임하고 툴팁으로 전체를 제공한다. 아주 긴 경로·큰 시스템 글꼴 조합은 추가 검증이 필요하다.
- 전체 탐색 항목은 최소 창에서 사이드바 스크롤이 필요하다. 기본 WPF 접기·선택 glyph와 일부 구형 보조창 표현도 후속 통일 대상이다.

## 공개 문서용 시각 기록

README 대표 화면과 [버전별 전후 비교](visual-history.md)를 추가했다. 기존 dev.1/dev.2 실행 파일을 별도 공개 예제 설정으로 다시 캡처했으며 사용자 환경 검증 원본과 구분한다. 공개 PNG·해시·검토 기록만 저장하고 개인 경로·타사 배경 썸네일이 포함된 원본은 제외했다. 제품 소스·기능·성능 측정은 이 문서화 작업에서 변경하지 않았다.

## dev.3 — 보조창·작은 창·반복 UI 작업 보정

dev.2 검토에서 남긴 최소 창 동작·중복 센서 상태·보조창 표현을 실제 Windows 화면으로 다시 확인했다.

| 이전 문제 | dev.3 구현과 이유 |
|---|---|
| 저장·취소가 폼과 함께 화면 밖으로 이동 | 공통 `DialogLayout`의 본문 ScrollViewer와 고정 오른쪽 동작 영역. 중첩 입력도 미저장 판단에 포함 |
| 최소 창에서 세션 저장/시작이 본문 아래 | 페이지 제목 아래 동작 유지. 프리셋은 좁을 때 선택 상자, 넓을 때 기존 목록 |
| 프로젝트 행의 메타데이터가 여러 줄로 늘어남 | 이름/최근 사용과 유형/Git의 두 줄, 즐겨찾기는 같은 행. 상세는 정보와 환경으로 구분 |
| 단계 사용/이동 시 전체 행 다시 생성 | ID별 기존 행·속성 재사용. 접힌 속성·로그 지연 생성 유지 |
| 갤러리 외부/내부 스크롤과 반복 템플릿 | 유한 뷰포트의 가상화 목록 하나, 창 수명 내 템플릿 재사용, 이미지 요청 합치기 |
| 팔레트 하단 안내·실행이 스크롤 아래 | 검색/하단 고정, 결과만 스크롤. 선택·빈 결과·프로젝트 문맥과 닫기 포커스 정리 |
| `설정 필요`/원시 품질 반복 | 건강 상태와 원인 설명을 나누어 결측을 간결하게 표시. 공급자/측정 값은 그대로 사용 |

확인된 문제는 반복 표기·빈 목록 공간·스크롤·동작 위치였다. 기존 화면에 없던 글로우/그라디언트를 제거했다고 주장하지 않는다. 로고·Midnight Purple·선택 테두리·기존 실행 서비스를 보존했다.

실제 화면 10개와 센서·프로필·디스플레이·Windhawk·정보 페이지를 추가 검토했다. Rainmeter는 소스 글꼴/정렬을 기존 배포 표현과 맞췄고, 숨긴 미터 좌표를 보존한 적용 후 위치·크기·측정 파일 해시를 확인했다. 수치·범위·남은 결함은 [dev.3 보고](v30-dev3-report.md)와 [성능](v30-performance.md)에 기록한다.
