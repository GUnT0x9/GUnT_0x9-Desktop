# README와 릴리스 화면 유지관리

README는 제품 소개·대표 화면·현재 버전·기능·빌드 진입점입니다. 기술 수치·전체 검증·변화 과정은 버전 보고서와 [시각 기록](visual-history.md)에서 관리합니다. 정식 릴리스·main의 공개 소스 기준·개발 프리뷰·실험 기능을 구분합니다. 다운로드 파일이나 배포 날짜는 실제 게시 근거가 있을 때만 추가합니다.

## 문서와 경로

- README: 공식 로고 → 현재 버전 → 대표 화면 → 기능 → 최신 변경 → 버전 기록 → 빌드 → 호환성 → 구조 → 로드맵 → 문서·크레딧.
- `CHANGELOG.md`: 실제 사용자에게 보이는 변경과 제한. 날짜·버전은 설정과 커밋/개발 보고로 확인합니다.
- `docs/visual-history.md`: 주요 버전의 목적·화면·전후 비교·한계·상세 보고 링크.
- `docs/images/releases/vX.Y/`: 새 주요 버전 이미지. 프리뷰는 `v3.0/dev.2/`처럼 버전을 구분합니다.
- `docs/images/releases/manifest.json`: 공개할 이미지의 해시, 버전, 출처, 시점 근거, 개인정보 검토와 권리 범위.
- `screenshots/`: Git에서 제외한 원본·검토용 내보내기·실행 manifest. 원본을 덮어쓰지 않습니다.

기존 `docs/images/v25-*.png`, `v26-*.png`의 공개 경로는 유지합니다. 같은 이미지를 새 폴더로 복제하지 않고 manifest와 문서에서 참조합니다. 없는 역사 이미지를 만들거나 새 화면을 옛 버전으로 표시하지 않습니다.

## 캡처 대상 선택

작은 UI 변경은 2–4개, 큰 기능 변경은 4–8개를 출발점으로 삼되 필요한 수만 선택합니다. 대표 화면·새 기능·바뀐 흐름·비교 화면 순으로 고릅니다. 비슷한 상태를 반복하거나 꾸미기용 이미지를 추가하지 않습니다.

실제 Windows 빌드에서 캡처합니다. 웹 목업·이미지 생성·그려 넣은 성공 상태를 사용하지 않습니다. WSL의 PE 자동 실행이 동작하지 않으면 [명시적 Windows 실행 방법](v30-screenshots.md#실행-명령)을 사용하고, GUI를 실행할 수 없으면 미검증으로 남깁니다.

## 별도 공개용 상태

사용자 프로젝트·알림·배경·센서 설정을 공개용으로 바꾸지 않습니다. 문서용 별도 루트에 예제 데이터만 만듭니다. 예제 이름과 공개용 경로, 빈 실행 기록, 실제 예제 Git 저장소를 사용하고 설정되지 않은 도구는 그대로 표시합니다.

현재 제공하는 Windows PowerShell 도구는 개발 세팅·세션·팔레트·빠른 패널만 캡처합니다. 사용자별 Lively·센서를 읽는 화면은 기본 대상에 넣지 않았습니다. 실행/적용 버튼·전역 키 등록·Explorer 재시작을 요청하지 않습니다.

```powershell
# 기존 제어 센터/팝업을 정상 종료한 뒤, 검증한 실행 파일로 실행
powershell.exe -MTA -NoProfile -ExecutionPolicy Bypass -File .\scripts\capture-readme-demo.ps1 -Executable .\bin\GUNT.ControlCenter.exe -Version 3.0.0-dev.3
```

`C:\GUNT-DocDemo\<새 식별자>` 생성 권한과 Git for Windows가 필요합니다. 예제 Git 저장소의 작성자는 `Documentation Demo`, 주소는 예약된 `demo@example.invalid`이며 원격 저장소는 등록하지 않습니다. 실행 파일 해시는 로컬 capture manifest에 남깁니다. `-Version`은 **해당 소스로 검증한 실제 빌드 버전과 일치하게** 지정해야 하며 앱 버전을 바꿔 역사 화면을 꾸미는 용도가 아닙니다. 보존 빌드 비교는 해당 빌드·의존 DLL과 기록이 있는 경우에만 수행합니다.

캡처 중 원본은 고유한 `screenshots/readme-<버전>-<식별자>/`에 보존합니다. 실패한 수집을 통과로 기록하지 않습니다. 예제 디렉터리는 임의 삭제하지 않으며 불필요해졌을 때 도구가 만든 경로인지 확인한 후 정리합니다.

## 개인정보와 저작권 검토

원본을 열어 작은 글자까지 읽습니다. 계정명, 홈·개인 경로, 비공개 저장소, 이메일, 키·토큰·비밀번호, 알림·브라우저·채팅, 회사 자료, 내부 주소·IP, 장치 ID와 터미널 출력을 확인합니다. 자동 문자열/OCR 검사는 보조 수단입니다.

설치된 배경이라는 이유로 이미지·영상·썸네일의 배포 권한이 생기지 않습니다. 권리를 확인할 수 없으면 창만 캡처하거나 해당 이미지를 제외합니다. 기존 공개 이미지도 재사용할 때 다시 확인합니다. 원본에 오류·결측·미설정이 있으면 성공으로 대체하지 않습니다.

## 가림과 최종 내보내기

1. 원본을 먼저 검토하고 가릴 좌표를 기록합니다.
2. 별도 파일에서 민감 영역을 **완전히 불투명한 단색**으로 덮습니다. 흐림·픽셀화는 사용하지 않습니다.
3. RGB PNG로 새로 인코딩해 원본의 텍스트·EXIF·프로필·투명 레이어를 전달하지 않습니다.
4. 필요하면 폭 1200–1600px로 축소하되 한글·상태·버튼을 실제 크기로 읽어 봅니다. 작은 팝업은 확대하지 않습니다. 보통 1MiB 미만을 목표로 하고 화질을 우선합니다.
5. 내보낸 파일을 다시 열어 가림·글자·초점·잘림·불필요한 호버·다른 창 노출을 확인합니다. **검토 전에는 공개 폴더로 복사하지 않습니다.**

```powershell
.\scripts\export-readme-image.ps1 -Source .\screenshots\원본\developer-setup.png -Destination .\screenshots\검토\developer-setup.png -MaxWidth 1600
# 가림이 필요한 원본은 원본 픽셀 좌표의 JSON 배열 사용
.\scripts\export-readme-image.ps1 -Source .\screenshots\원본.png -Destination .\screenshots\검토\가림.png -MasksJson .\screenshots\masks.json
```

가림 JSON 형식은 `[{"x":100,"y":200,"width":500,"height":40}]`입니다. 축소 전에 가려 원래 픽셀이 축소 필터로 새어 나오지 않게 합니다. 검토한 파일만 버전 폴더로 **명시적으로 복사**하고 manifest에 실제 가림 여부를 기록합니다. 예제 데이터 덕분에 가림이 필요 없었다면 그대로 기록합니다. 두 상태를 같은 것으로 표시하지 않습니다.

## 새 버전 추가

README 현재 버전과 최신 업데이트를 교체하고 이전 내용은 버전 기록·상세 보고로 옮깁니다. 기존 크레딧·라이선스·복구·호환성 링크를 보존합니다. 최신 이미지에는 버전·실제 앱·예제 여부를 alt text와 캡션으로 설명합니다. 전후 비교는 가능한 같은 창 크기·DPI·데이터 구조로 만들고 차이를 기록합니다.

```markdown
### vX.Y — 변경 목적

**근거 있는 개발/릴리스 날짜.** 실제 바뀐 동작과 남은 제한을 적습니다.

[실제 화면](docs/images/releases/vX.Y/changed-screen.png) · [상세 보고](docs/version-report.md)
```

성능을 다시 재지 않았다면 기존 수치를 새로운 릴리스의 측정값으로 재사용하지 않습니다. 화면 정리가 CPU·메모리 감소를 증명하지 않습니다.

## 검사와 게시

```powershell
python .\scripts\check-readme-docs.py
# 원본이 섞이지 않도록 실제 변경 파일만 각각 지정
git diff -- README.md CHANGELOG.md docs/
git diff --cached --name-only
git diff --cached --check
```

검사 스크립트에는 Python 3.9 이상과 표준 라이브러리만 필요합니다.

검사 도구는 README와 Markdown 상세 링크를 따라가 파일·앵커·이미지를 확인하고, public manifest의 PNG 크기·CRC·압축 데이터·메타데이터·해시·중복을 검사합니다. 새로운 릴리스 이미지가 manifest에서 빠지면 실패합니다. **시각 개인정보·저작권 검토를 자동 승인하지 않습니다.**

Git 변경에는 README·보고서·검토한 public PNG·manifest·관리 스크립트만 포함합니다. `screenshots/`, `logs/`, `state/`, `backups/`, runtime 설정·Dock 사용자 변경은 스테이징하지 않습니다. `git add -A`를 사용하지 않습니다.

검토가 끝나면 문서 커밋을 만들고 승인된 대상 개발 브랜치에 일반 push합니다. 실패하면 게시됐다고 보고하지 않습니다. main 갱신·강제 push·안정 릴리스는 별도 작업입니다. 새 버전 작업의 완료 조건에 이 절차를 포함하되 개인정보 검토와 게시를 무조건 자동화하지 않습니다.

## dev.3에서 확장한 캡처 옵션

`capture-readme-demo.ps1`의 `-WidthDip 780 -HeightDip 560`은 작은 본문 창을, `-ProjectEditor`는 개발 세팅의 실제 보조 편집창을 추가 캡처합니다. 기본은 1400×860 DIP입니다. `-Pages` 배열은 Windows PowerShell에서 `@('developer-setup','development-sessions')`처럼 전달합니다. 편집창에서는 값을 바꾸지 않고 닫습니다. 캡처 전에 포인터를 창 밖으로 옮기고 종료 후 원위치로 돌립니다.

보존 버전 비교는 의존 DLL을 갖춘 실제 과거 실행 파일을 지정합니다. 현재 소스에 과거 버전 문자열만 붙여 역사 화면을 만들지 않습니다. 창 크기·DPI·데이터·캡처 날짜 차이를 비교 설명과 manifest에 남깁니다.
