# 3.0.0-dev.2 성능 결과

## 측정 조건

2026-10-19 실제 Windows, 동일 사용자 데이터·전원·연결 화면에서 dev.1 네이티브 빌드와 dev.2 후보를 각각 5회 교차 실행했다. 기준 실행 파일은 dev.1 소스 변경 전에 기존 Windows 도구로 빌드해 보존한 파일이다. 두 실행 파일과 동일 의존 DLL을 같은 깊이의 별도 폴더에 두었다.

본문 측정 창은 1180×800 DIP, 실제 DPI 168(175%)이다. OS 캐시를 초기화하지 않았으므로 콜드 시작으로 부르지 않는다. 팔레트는 **제어 센터 내부에서 연 소유 팝업**이며 독립 프로세스 시작과 구분한다. UIA와 선택적 로컬 계측을 사용했다.

## 결과

단위 ms. 괄호는 최소–최대이며 중앙값을 먼저 표시한다.

| 지표 | dev.1 | dev.2 | 해석 |
|---|---:|---:|---|
| 창 첫 프레임, 5회 | 446.770 (403.908–494.231) | 452.042 (414.724–483.006) | 범위가 겹침. 시작 성능 개선 확정 안 함 |
| 프로젝트 페이지 초기 구성, 5회 | 54.846 (53.202–65.302) | 44.063 (41.118–53.584) | 이번 표본 중앙값 약 19.7% 감소 |
| 세션 페이지 초기 구성, 5회 | 21.126 (19.893–25.710) | 43.816 (42.764–55.943) | 본문 편집기 추가 비용, 증가를 숨기지 않음 |
| 갤러리 초기 구성, 5회 | 14.816 (11.904–17.983) | 22.827 (15.274–23.901) | 적응형 타일 구성 비용 증가 |
| 내부 팔레트 첫 프레임, 5회 | 126.182 (72.436–146.188) | 118.771 (81.268–121.946) | 변동 범위가 겹침 |
| 팔레트 검색, 25회 | 1.412 (0.402–7.503) | 1.232 (0.477–6.868) | 같은 5종 입력 반복. 백엔드 개선율로 해석 안 함 |

페이지 구성 시간은 비동기 Git·상태·메타데이터 완료, 전체 이미지 로딩, 최종 페인트 완료를 포함하지 않는다. 검색 계측은 필터와 결과 소스 갱신까지다.

| 유휴 관찰 | dev.1 | dev.2 |
|---|---:|---:|
| 작업 집합 중앙값 | 196.363 MiB | 199.336 MiB |
| 전용 메모리 중앙값 | 166.410 MiB | 169.395 MiB |
| CPU (논리 CPU 수로 정규화) | 0.115% | 0.192% |

최종 후보 SHA-256은 `3eefc348f7d2bdcd5002aa71bdaaf29fa73550e1d6845b5ceea7a8482a8ec920`다. 캡처와 상호작용 검사에도 같은 실행 파일을 사용했다.

유휴 수치는 마지막 실행에서 1초 간격 5회 관찰했다. 관찰 시간이 짧아 CPU 절감·배터리 절감·장시간 누수 부재를 확정하지 않는다. 작업 집합은 약 3MiB 증가했고 CPU 관찰값도 증가했다. 이 구간에는 자동 메모리 회수에 따른 하락이 있어 단일 짧은 구간을 상시 비용으로 일반화하지 않는다.

## 구현과 검사

- 프로젝트 선택 저장과 Git·파일 탐지는 UI 스레드에서 분리. 빠른 이동에서도 새 문맥을 기다려 기존 실행 서비스에 전달.
- 실현된 프로젝트 행만 메타데이터 조회, 동시 요청 2개. 검색은 메모리 필터.
- 접힌 세션 속성과 전체 이력을 실제로 펼칠 때 생성.
- 기본 가상화 목록이 그리드 행 묶음을 재활용. 240px 썸네일·최대 64개 캐시 유지.
- UI에 반영하는 비동기 완료를 Dispatcher로 전달. 종료 중 취소 처리.
- 키마다 반복되던 단축키 JSON 읽기 제거. 활성화·설정 작업 후 갱신.

격리된 실제 WPF 검사에서 프로젝트 500건의 실현 컨테이너는 24개 미만, 배경 500건의 실현 행 묶음은 16개 미만·이미지는 80개 미만이었다. 스크롤 후에도 가상화를 유지하고 서로 다른 썸네일을 읽어 캐시 64개 상한을 확인했다. 이는 실제 사용자 데이터가 500건이었다는 뜻이 아니다.

썸네일 전체 로딩 시간·장시간 CPU·물리 다중 화면의 성능은 미측정이다. 기존 WinForms 자원 정리 코드를 이번 단계의 새 절감 효과로 다시 계산하지 않는다.

## 재현

Windows PowerShell에서 앱 창을 먼저 닫고 실행한다. 기존 창을 강제 종료하지 않는다.

```powershell
Set-Location 'C:\Users\김건트\GUNT-Desktop'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-control-center.ps1
powershell.exe -MTA -NoProfile -ExecutionPolicy Bypass -File .\scripts\measure-v30-ui.ps1 -BaselineExecutable '기준빌드\GUNT.ControlCenter.exe' -CandidateExecutable '.\bin\GUNT.ControlCenter.exe' -Samples 5
```

기준 빌드는 dev.1을 별도 worktree에서 기존 Windows 도구로 빌드하고 의존 DLL과 함께 보존한다. 현재 작업 트리를 reset하거나 사용자 설정을 기준 버전으로 되돌리지 않는다. 두 빌드에 같은 현재 사용자 데이터를 전달한다.

원자료: `logs/v30-dev2-benchmark.json`. 실행 파일 SHA-256, 각 표본·범위, 비동기 제외 범위, 실패 여부를 기록한다. 실패한 자동화 실행의 부분 표본을 위 표에 섞지 않았다. `GUNT_UI_METRICS=1`인 앱만 `logs/v30-ui-timings.jsonl`에 경로·검색어 없는 계측을 추가한다. 기본 실행에는 이 로그 I/O가 없다. 원자료는 Git에서 제외한다.
