현재: [dev.3 전후 비교](#dev3--2026-10-20-전후-비교). dev.2 수치는 당시 기록으로 보존한다.

## dev.2 측정 조건

2026-10-19 실제 Windows, 동일 사용자 데이터·전원·연결 화면에서 dev.1 네이티브 빌드와 dev.2 후보를 각각 5회 교차 실행했다. 기준 실행 파일은 dev.1 소스 변경 전에 기존 Windows 도구로 빌드해 보존한 파일이다. 두 실행 파일과 동일 의존 DLL을 같은 깊이의 별도 폴더에 두었다.

본문 측정 창은 1180×800 DIP, 실제 DPI 168(175%)이다. OS 캐시를 초기화하지 않았으므로 콜드 시작으로 부르지 않는다. 팔레트는 **제어 센터 내부에서 연 소유 팝업**이며 독립 프로세스 시작과 구분한다. UIA와 선택적 로컬 계측을 사용했다.

## 구현과 검사

- 프로젝트 선택 저장과 Git·파일 탐지는 UI 스레드에서 분리. 빠른 이동에서도 새 문맥을 기다려 기존 실행 서비스에 전달.
- 실현된 프로젝트 행만 메타데이터 조회, 동시 요청 2개. 검색은 메모리 필터.
- 접힌 세션 속성과 전체 이력을 실제로 펼칠 때 생성.
- 기본 가상화 목록이 그리드 행 묶음을 재활용. 240px 썸네일·최대 64개 캐시 유지.
- UI에 반영하는 비동기 완료를 Dispatcher로 전달. 종료 중 취소 처리.
- 키마다 반복되던 단축키 JSON 읽기 제거. 활성화·설정 작업 후 갱신.

격리된 실제 WPF 검사에서 프로젝트 500건의 실현 컨테이너는 24개 미만, 배경 500건의 실현 행 묶음은 16개 미만·이미지는 80개 미만이었다. 스크롤 후에도 가상화를 유지하고 서로 다른 썸네일을 읽어 캐시 64개 상한을 확인했다. 이는 실제 사용자 데이터가 500건이었다는 뜻이 아니다.

썸네일 전체 로딩 시간·장시간 CPU·물리 다중 화면의 성능은 미측정이다. 기존 WinForms 자원 정리 코드를 이번 단계의 새 절감 효과로 다시 계산하지 않는다.

## 재현

아래 `C:\src\GUNT-Desktop`은 설명용 경로다. 실제 체크아웃 경로로 바꾼다. Windows PowerShell에서 앱 창을 먼저 닫고 실행한다. 기존 창을 강제 종료하지 않는다.

```powershell
Set-Location 'C:\src\GUNT-Desktop'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-control-center.ps1
powershell.exe -MTA -NoProfile -ExecutionPolicy Bypass -File .\scripts\measure-v30-ui.ps1 -BaselineExecutable '기준빌드\GUNT.ControlCenter.exe' -CandidateExecutable '.\bin\GUNT.ControlCenter.exe' -Samples 5
```

기준 빌드는 dev.1을 별도 worktree에서 기존 Windows 도구로 빌드하고 의존 DLL과 함께 보존한다. 현재 작업 트리를 reset하거나 사용자 설정을 기준 버전으로 되돌리지 않는다. 두 빌드에 같은 현재 사용자 데이터를 전달한다.

원자료: `logs/v30-dev2-benchmark.json`. 실행 파일 SHA-256, 각 표본·범위, 비동기 제외 범위, 실패 여부를 기록한다. 실패한 자동화 실행의 부분 표본을 위 표에 섞지 않았다. `GUNT_UI_METRICS=1`인 앱만 `logs/v30-ui-timings.jsonl`에 경로·검색어 없는 계측을 추가한다. 기본 실행에는 이 로그 I/O가 없다. 원자료는 Git에서 제외한다.

## dev.3 — 2026-10-20 전후 비교

### 조건과 원자료

dev.2 보존 바이너리(소스 변경 전 보존)와 dev.3 최종 바이너리를 각각 **5회 교차 실행**했다. 홀짝 회차마다 실행 순서를 뒤집었다. 같은 현재 사용자 설정·프로젝트/배경 데이터와 1180×800 DIP, 실제 Windows 175%에서 측정했다. 두 빌드의 의존 DLL과 디렉터리 깊이를 같게 했다. WSL `/init`을 통해 Windows PowerShell/.NET Framework 4.8에서 실행했다.

OS 파일 캐시·다른 프로그램·전원/스케줄링은 통제하지 않았다. 콜드 시작이나 순수 벤치마크 머신으로 부르지 않는다. 표본은 UIA와 선택 계측의 비용을 포함한다. 구성 시간은 비동기 Git/WSL/센서/배경 메타데이터 완료나 전체 썸네일 표시까지의 시간이 아니다. 팔레트는 제어 센터 소유 창이며 별도 프로세스 팝업과 구분한다.

- 최종 SHA-256: `5e63b09bd5791bf386643134dc955bcfe94a6cdc7fbd5085f0ee58013e3b11c4` (`451e1cc`, 센서 직접 시작의 Dispatcher 보정 포함).

### 실제 세션 편집 동작

CPU는 앞선 실행들에서 증가/감소가 모두 나타났으므로 이 5초만으로 절감을 확정하지 않는다. 템플릿/행 재사용과 새 레이아웃의 수명 비용을 더 긴 탐색으로 검사해야 한다. WinForms 상단 바는 기존 자원 소유 코드를 유지했으며 이번 3표본 GDI 81/USER 49 동일 관찰만으로 새 최적화·누수 해결을 주장하지 않는다.

### 구현과 기능 검증

- 단계 ID별 컨트롤·펼친 속성을 재사용. 프로젝트 환경은 페이지 진입에 읽고 명시적 변경 후 갱신. 미리보기 타이머는 이동 시 중지.
- 창별 갤러리 템플릿 재사용, 동일 배열/열의 중복 재배치 생략, 배열 묶기, 동일 썸네일 요청 합치기·동시 작업 2개. 디코딩 240px·캐시 64개 유지.
- 갤러리를 벗어날 때 목록 이미지 참조와 watcher 작업 제한. 새 페이지에는 새 상태를 읽어 무기한 오래된 설정 캐시를 만들지 않음.
- 센서 선택 목록은 백그라운드 조회 후 현재 페이지/요청 세대가 같을 때만 반영. 명령 관리 검색의 설정은 페이지 스냅샷으로 재사용하고 즐겨찾기/별칭 저장 뒤 갱신.
- 실제 WPF 42개 검사에서 500개 프로젝트/배경 가상화·재활용·64개 캐시, 단계 재사용·저장/미저장·단위/도구 편집을 확인. 500개는 격리 예제이며 실제 설치 데이터 수로 표시하지 않음.

### dev.3 재현 명령

Windows PowerShell에서 실제 체크아웃 경로로 이동하고 기존 앱을 정상 종료한다. 과거 빌드+DLL과 현재 빌드+DLL을 별도 디렉터리에 보존해 비교한다. 사용자 설정을 과거 버전으로 reset하지 않는다.

```powershell
powershell.exe -MTA -NoProfile -ExecutionPolicy Bypass -File .\scripts\measure-v30-ui.ps1 -BaselineExecutable '기준빌드\GUNT.ControlCenter.exe' -CandidateExecutable '후보빌드\GUNT.ControlCenter.exe' -Samples 5 -ResultLabel dev3-final
powershell.exe -STA -NoProfile -ExecutionPolicy Bypass -File .\scripts\measure-v30-session-editor.ps1 -Executable '후보빌드\GUNT.ControlCenter.exe' -Label dev3-after-editor-1 -Samples 20
```

단계 측정도 기준/후보를 각각 새 PowerShell 프로세스로 3회 교차 실행한다. `-ResultLabel`/`-Label`을 바꾸어 이전 원자료를 보존한다. 개인 원자료·바이너리는 Git에 넣지 않는다.
