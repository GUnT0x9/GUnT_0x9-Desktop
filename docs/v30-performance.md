# 3.0 성능 점검

## 측정 상태

**실제 앱 전후 성능 표본 없음. 개선율·메모리 절감량·CPU 절감량을 주장하지 않는다.**

Windows 실행은 일반/권한 상승 모두 `Exec format error`로 실패했다. Linux에서 SDK 8.0.426의 Roslyn, C# 5, Microsoft.NETFramework.ReferenceAssemblies.net48 1.0.3으로 교차 컴파일했다. 이는 제품 런타임 변경이 아니다. 산출물은 임시 폴더에만 생성했으며 기존 `bin` 실행 파일을 교체하지 않았다.

| 지표 | 이전 | 이후 | 현재 판단 |
|---|---|---|---|
| 실제 콜드/웜 시작 | 미측정 | 미측정 | Windows 필요 |
| 페이지 이동·반응 | 미측정 | 미측정 | 소스 경로 개선만 확인 |
| 팔레트 표시·검색 | 미측정 | 미측정 | 검색 규칙 10개 회귀 통과 |
| 프로젝트 검색 | 미측정 | 미측정 | 검색 시 Developer 설정 재파싱 제거 |
| 갤러리 로딩 | 미측정 | 미측정 | 전체 컨트롤 선생성 제거 |
| 유휴 CPU·메모리 | 미측정 | 미측정 | Windows 반복 표본 필요 |
| 상단 바 GDI 자원 | 미측정 | 미측정 | 소유 자원 수명 코드 보완 |

## 소스에서 확인한 작업과 수정

- 팔레트: `SearchCommands(query, commands, config)` 오버로드로 열린 창의 검색 데이터 재사용. 기존 기본 별칭·사용자 별칭·점수·즐겨찾기·최근 순서·60개 제한을 유지한다. 실행 시에는 기존 서비스가 명령을 다시 검증한다. 표시 후 프로젝트 ID/경로가 바뀌면 재확인을 요구한다.
- 프로젝트 검색: 개발 설정을 문자마다 다시 읽지 않는다. 선택 유지·검색 해제·지연된 Git 결과의 세대 검사를 적용한다. Git 조회는 기존 비동기·읽기 전용 서비스를 사용한다.
- 상태·센서: 개요·진단 Health와 센서 표시 문자열 생성을 작업 스레드로 이동한다. 폴링이 겹치지 않으며 숨김/최소화 창은 기존 정책대로 건너뛴다. UI 상태 타이머만 3초에서 5초로 조정하며 Rainmeter 측정/샘플 간격은 변경하지 않는다.
- 갤러리: 메타데이터/배치 조회를 비동기로 수행한다. 데이터 기반 재활용 목록에서 실현된 이미지의 로딩을 요청한다. 이미지 폭 240px, Freeze/OnLoad, 최대 64개 캐시와 파일 수정시각 키를 사용한다. 목록 필터링은 메모리에서 수행한다. 기존 Lively 렌더러·배경 선택은 유지한다.
- 상단 바: 툴팁 폰트 재사용, 재구성 시 레이아웃 일괄 처리, 아이콘 색상 ImageAttributes 재사용, 이전 메뉴 항목·팝업 메뉴·프로세스 객체·타이머 정리. 기본 작업 표시줄·Explorer·Windhawk 동작은 수정하지 않는다.
- 공통 스타일: XAML 리소스를 공유한다. 페이지 전체 사전 생성이나 새 백그라운드 서비스는 추가하지 않는다.

## 재현 절차

1. 같은 Windows PC, 같은 전원 상태·화면·프로젝트/배경 데이터·프로그램 부하를 사용한다. OS 캐시를 초기화하지 않은 첫 실행을 콜드 시작으로 부르지 않는다.
2. v2.6 기준을 별도 작업 디렉터리에서 빌드해 기준 측정을 먼저 수행한다. 실제 사용자 설정을 초기화하거나 현재 배경을 바꾸지 않는다.
3. `scripts/verify-v30-ui.ps1 -Label before -Samples 5` 실행 후 현재 개발 빌드를 준비하고 `-Label after -Samples 5`를 실행한다. 스크립트는 현재 열려 있는 제어 센터가 있으면 중단한다.
4. 로그는 `logs/v30-ui-before.json`, `logs/v30-ui-after.json`. 중앙값·최소/최대·메모리 표본·실제 DPI를 함께 비교한다. UIA 선택 왕복 시간은 페이지 렌더 완료 시간이 아니다.
5. `GUNT_UI_METRICS=1`인 프로세스만 `logs/v30-ui-timings.jsonl`에 first-render/page-build/search 시간을 기록한다. 페이지 구성 시간은 비동기 조회 완료를 포함하지 않는다. 실행마다 로그를 분리해 보관한다. 측정 로그는 Git에서 제외된다.
6. 기존 `measure-v24-performance.ps1`을 동일 시나리오로 추가 실행해 다른 프로세스 부하를 분리할 수 있다.

계측은 선택 기능이며 기본 실행에는 로그 I/O가 없다. 계측을 켠 실행에서는 동기식 로컬 로그 쓰기 비용을 고려해야 한다.

## 교차 컴파일과 소스 검사

```bash
python3 scripts/check-v30-source.py
python3 scripts/check-v30-search.py --dotnet /path/to/dotnet
python3 scripts/compile-v30-linux.py --dotnet /path/to/dotnet --references /path/to/.NETFramework/v4.8
```

검색 검사 10개, 기존 목적지 19개 보존, XAML XML 구문 5개, 라이브러리 2개·실행 파일 2개 컴파일 통과. 기존 `SettingField.cs`의 CS9258 정보 메시지는 남아 있으며 컴파일 오류가 아니다. XML 파싱은 WPF 템플릿 로딩 검증이 아니다. Windows 수집 스크립트는 Linux PowerShell 7.4.6에서 구문 파싱을 통과했으며 Windows 동작은 실행하지 않았다.
