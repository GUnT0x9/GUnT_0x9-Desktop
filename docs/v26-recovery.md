# v2.6 복구

## 범위

구현 전 `pre-v26-developer-workspace` 체크포인트에 이전 소스·실행 파일·관련 설정 498개 파일을 보관했습니다. 백업 경로·파일 SHA256은 로컬 `state/pre-v26-developer-workspace-checkpoint.json`에 있습니다. 공개 Git에는 개인 백업·미디어를 올리지 않습니다.

```powershell
# 먼저 실제 변경 없이 현재 적용 파일과 백업 해시를 검사
.\scripts\rollback-v26-developer.ps1 -Component All -WhatIf

# 저장하지 않은 편집이 없도록 제어 센터를 닫은 후 필요한 코드만 복원
.\scripts\rollback-v26-developer.ps1 -Component ControlCenter
.\scripts\rollback-v26-developer.ps1 -Component TopBar
# 공용 설정 코드까지 함께 되돌릴 때
.\scripts\rollback-v26-developer.ps1 -Component All
```

기존 `rollback-v25-ux.ps1`의 검증·직전 코드 백업·정상 종료·실패 시 직전 파일 복원 절차를 재사용합니다. 적용 후 파일 해시가 달라졌으면 사용자 수정을 덮지 않고 중단합니다. 원본이 없던 신규 소스는 삭제하지 않고 복구 직전 백업으로 이동합니다. 상단 바 복원은 프로젝트 자체 상단 바만 정상 종료/시작하며 Explorer를 재시작하지 않습니다. 미저장 제어 센터를 강제 종료하지 않습니다.

실제 사용자 프로젝트·개발 기본값·세션·별칭·규칙·현재 배경은 이 **코드 복구에서 보존**합니다. Windhawk·Rainmeter·Lively 전체 초기화를 하지 않습니다. 테마의 표시 버전·새 단축키 개인 설정은 보존되며 구형 실행 파일은 미지원 값을 사용하지 않습니다.

## 프로젝트 형식

v2.6은 기존 프로젝트 DB 버전 1을 읽고 저장 시 버전 2로 씁니다. 추가 Developer 설정을 보존하기 위해 구형 v2.5 작성기는 버전 2 편집을 거부합니다. 코드 복구 후 프로젝트 목록 편집이 필요하면 v2.6으로 돌아오거나, 개인 백업을 비교한 별도 마이그레이션을 하세요. 버전 번호만 수동으로 낮춰 저장하면 새 필드를 잃을 수 있으므로 그렇게 복구하지 않습니다.

## 자동화·실행

자동화를 끄려면 규칙 목록의 사용 상태를 중지합니다. 세션 종료 기록은 편집기·터미널을 종료하지 않습니다. 자동화 소유 복원은 최신 한 단계의 관리 값이 예상과 같을 때만 수행하며, 이후 수동 변경이 있으면 거부합니다. 배경 패키지·원래 위치를 강제로 덮지 않습니다.

## 확인 상태

복구의 `-WhatIf`는 적용 파일·체크포인트의 해시와 계획을 확인하는 검사입니다. 실제 전체 코드 복원을 실행한 뒤 기능·화면을 검증한 결과로 대신 표시하지 않습니다. 복구 후에는 소스와 실행 파일이 같은 버전인지 확인하고 필요한 모델 검사·창 실행을 다시 수행하세요.
